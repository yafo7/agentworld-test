# 奇异岛 & 鬼屋 — 多 Demo 3D 创造游戏技术验证平台

基于 Three.js + Vite 的 AI 驱动 3D 创造引擎，验证"文字 → 3D object → 交互演化"的 gameplay 管线。

> 核心技术：以 **tag（卡牌）** 为底层 DNA，驱动所有 object 的生成、交互与演化；文字产生 objects → 围绕 3D 自由创造构建以"创造"为核心的玩法系统。

---

## Demo 1: 奇异岛（Chii Island）

**类型：** 3D 模拟养成 × 轻 RTS 经营

**一句话：** 玩家不是"抓宠物然后养"，而是"先创造一个值得生命到来的地方，然后观察什么样的生命愿意住进来"——进而派遣它们工作、战斗、社交，逐步开拓属于自己的奇异岛屿。

**背景：** 玩家作为一名待业青年画家，偶然在求职 app 上看到"奇异岛"的招聘，决定前往试试。目的地是一座"奇异岛"，岛上的生命由环境的"tag"孕育而生。

**关键词：** 筑巢、等待、邂逅、观察、照顾、共生、变化、收藏、产生故事、派遣、开拓、进化。

### 核心玩法循环

```
玩家在 3×3 世界网格（9个单位环境）上漫游
  |
  ├─ E靠近宠物小屋 → 召唤宠物（马扣/扶摇/momo）在旁边一格生成
  |       └─ 再次E靠近小屋 → 宠物走回旁边一格 → 停顿 → 消失（可重新召唤）
  |
  ├─ 靠近宠物 → E抚摸 → 亲密度+1
  |       ├─ lv5: AI 生成新物品
  |       └─ lv10: AI 生成新环境 + 宠物寻主对话（⚠️ 暂时关闭）
  |
  ├─ 靠近装饰/建筑/树木 → E交互 → 播放 AI 生成交互动画（若有）或呼吸动画
  |
  ├─ 靠近风铃 → E捡起 / 再次E放下
  |
  ├─ 宠物跟随与改造系统
  |       ├─ H 靠近宠物 → 呼喊跟随（可多宠同时跟随）
  |       ├─ J → 解散所有跟随中的宠物（进入 30s linger 后自动回家）
  |       └─ R → 所有跟随宠物一起去 refine 离玩家最近的实体
  |
  ├─ 宠物 refine 系统（万物皆可 refine）
  |       ├─ 宠物寻找最近带模型的实体（装饰/树木/环境/建筑/宠物/物品）
  |       ├─ 走向目标 → 转圈 → 优先调用后端 refineModel API 基于原模型改造
  |       ├─ 无 AI metadata 时 fallback 到 generateModel 重新生成
  |       ├─ 改造保留原模型特征，新增一个 tag 相关特色
  |       ├─ 从所有参与宠物的 tag 中各抽一个，合并后追加给被 refine 目标
  |       └─ StaticEntity 被 refine 后获得 AI 生成交互动画，按 E 播放
  |
  ├─ 进入外围环境 → 右上角提示 "按P展示/隐藏该地形内容"
  |       └─ 按O全局显示/隐藏所有外围环境（一键回到单中心场景）
  |
  ├─ G 键放置占位符
  |       └─ 在玩家脚下最近的空闲单位面积上放置装饰类型占位符
  |               （橘色体素模型，占用并染黄该单位面积；重复放置屏幕中央提示"不可重复放置"）
  |               放置后立即可被右侧模型编辑器识别和修改
  |
  ├─ F 键清除装饰
  |       └─ 清除玩家附近最近的装饰类实体（占位符/预放置装饰），不作用于房屋/树木
  |               清除后释放网格占用并恢复地块默认灰色
  |
  ├─ 场景本地持久化
  |       └─ 所有场景修改实时写入 `localStorage`（key: `chii-island-scene`）
  |               刷新页面后自动恢复：已放置/删除的装饰、编辑器替换的模型与动画、
  |               环境显隐状态、宠物召唤状态与亲密度、物品位置
  |               清除 localStorage 后刷新可回到初始基线状态
  |
  ├─ 右侧常驻模型编辑器（左右分栏）
  |       ├─ 自动加载靠近的实体模型到预览画布
  |       ├─ 预览：鼠标拖拽自由旋转（水平 + 垂直），滚轮缩放，松开后自动缓慢旋转
  |       ├─ 输入描述词 → 重新生成 / 改造
  |       ├─ 生成/改造的 voxel 模型自动保存到"已生成模型"库（public/generated/ + localStorage fallback）
  |       ├─ 📚 从模型库选择：云端 GLTF + 本地 public/generated/ 体素模型 + 已生成模型 + 体素工作室模型
  |       ├─ ✨ 新建动画：输入描述生成 Motion Plan，选择 "E 交互"（默认）或 "idle 循环"
  |       ├─ 🎬 动画库：以模型为单位存储多组动画，支持预览、切换、应用为 E 交互/idle、删除
  |       └─ 确认替换 → 游戏中该实体立即更换为新模型与新动画
  |
  └─ 屏幕底部实时显示 "xxx 按E互动/呼唤/召回/抚摸/捡起/呼喊跟随" 提示
```

### 世界系统

| 系统 | 说明 |
|------|------|
| 世界网格 | 3×3 单位环境矩阵，间距 23。中心为玛扣大森林，周围 8 个差异化环境 |
| 单位面积 | 2×2×0.1 灰色体块，顶部齐平 Y=0，向下延伸不遮挡物体 |
| 单位环境 | 10×10 离散地块网格，单位面积之间留 0.05 缝隙。通过 `paintUnitArea()` 按类型染色 |
| 环境染色 | 树=浅绿 / 装饰=浅黄 / 宠物小屋=浅红 / 默认=灰色 |
| 环境实体 | 9 个环境各有一个中心主题模型（tree_marko/pond/grassland/forest/trainer/sun_stone 等） |
| 按需加载 | 外围 8 个环境默认隐藏物品；`O` 全局切换显隐，`P` 单环境切换显隐 |
| 场景持久化 | 通过 `src/storage/sceneSnapshot.js` 实时保存场景快照到 `localStorage`；刷新后自动恢复所有场景修改 |

### 实体与宠物系统

| 实体 | 说明 |
|------|------|
| 玩家 | 哪吒模型（player-nezha.json），WASD 直接向量移动，空格跳跃，左键拖拽旋转相机，滚轮缩放 |
| 宠物 | 马扣（小马行走）/扶摇（小鸟飞翔）/momo（团子行走），模型+idle/walk动画，50%缩放，完整亲密度/状态机 |
| 装饰品 | ps5/ns2/雷霆大雪绒/苔藓灯/风铃/太阳石/训练桩等（StaticEntity），半尺寸，不可移动 |
| 宠物小屋 | 马扣的家/扶摇的家/momo的家 + 各环境主题小屋，半尺寸，红色单位面积 |

### 交互优先级

| 按键 | 功能 |
|------|------|
| E | 6 级优先级：掉物 > 宠物抚摸 > 小屋召唤/召回 > 静态实体交互动画 > 捡起风铃 |
| H | 靠近宠物 → 呼喊该宠物跟随（支持多宠同时跟随） |
| J | 解散所有跟随中的宠物（进入 30s linger 后自动回家） |
| R | 所有跟随宠物一起去 refine 离玩家最近的实体 |
| G | 在玩家脚下空闲单位面积放置装饰类型占位符；该面积已被占用时屏幕中央提示不可重复放置 |
| F | 清除玩家附近最近的装饰类实体（占位符/预放置装饰），不作用于房屋/树木 |
| P | 在当前外围环境内，切换该环境物品的显示/隐藏 |
| O | 全局切换所有外围环境的显示/隐藏（一键回到单中心场景） |

## Demo 2: 鬼屋（Ghost Home）⭐ 概念策划中

**类型：** 双人 / Party Game

**一句话：** 作为一个居住在古老庄园内的鬼魂，你的工作是怎样让这个庄园变成真正意义上的"鬼屋"！

### 核心概念

**非对称对抗双人游戏**：两名玩家扮演同一只鬼魂的两个不同面向，目标截然相反。

| 角色 | 目标 | 玩法 |
|------|------|------|
| **玩家1（友善鬼）** | 让庄园变得更好，吸引更多人类住进来 | 布置家具、改善装饰、让房子温馨舒适 |
| **玩家2（捣蛋鬼）** | 赶走所有人类，坐实闹鬼传说 | 魔改房子装饰、增加诡异动画、吓唬住户 |

### NPC 住户系统

买下庄园的新主人带着一家老小入住：
- **严肃的男主人** — 理性派，不易被吓到，但发现异常会找人调查
- **勤劳的女主人** — 对房子环境敏感，装饰变化会影响她的心情
- **喜欢摸索的小男孩** — 好奇心重，会触发隐藏机关和秘密
- **拥有灵视的女孩** — 唯一能看到鬼魂真身的家庭成员，关键剧情触发点

### 不速之客

当庄园传出诡异传说后，外来者陆续到达：
- **灵异故事探险者** — 带着摄像头和探测仪来"找茬"，需要躲开他们的追查
- **神父** — "我不允许有这样不属于上帝的不洁之地"，前来驱魔，是鬼魂的最大威胁

### 核心循环

```
新住户搬进庄园
  |
  ├─ 玩家1 布置温馨家具 → 住户满意度↑ → 吸引更多住户
  |       └─ 但玩家2 随时可以把家具魔改成恐怖版本...
  |
  ├─ 玩家2 激活诡异动画/机关 → 住户恐惧值↑ → 住户逃跑
  |       └─ 但玩家1 可以修复和安抚...
  |
  ├─ 女孩发现鬼魂迹象 → 剧情分支
  |       ├─ 被玩家1 引导 → 成为朋友 → 隐藏结局
  |       └─ 被玩家2 利用 → 灵视失控 → 庄园暴露
  |
  ├─ 探险者/神父到达 → 限时躲避阶段
  |       ├─ 躲避摄像头和探测仪范围
  |       └─ 神父驱魔仪式 → 需要破坏仪式或转移注意力
  |
  └─ 庄园名声扩散 → 更多住户 or 更多猎魔人？
```

### 当前实现状态

Ghost Home 已完成最小可运行框架，直接复用 Chii Island 的 3×3 世界网格场景与全部交互逻辑，但移除了所有非玩家模型：

- 场景内保留 3×3 单位环境地形网格，无环境中心模型、无树木、无房屋、无宠物、无物品
- 玩家角色（哪吒模型）可正常移动、跳跃、旋转相机
- 保留右侧分屏模型编辑器、底部交互提示、G/O/P 键交互逻辑、点击检查（raycast）
- 用户反馈在特定环境下 Ghost Home 页面无法打开，本地 Playwright 与生产构建测试均正常，问题待进一步排查

**访问地址：** `http://localhost:5173/src/demos/ghost-home/index.html`

## 共享技术栈

- **Three.js** `^0.184.0` — 3D 渲染
- **Vite** `^8.0.12` — 开发与构建
- **DeepSeek API** — 文本侧 AI（对话/概念/里程碑生成）
- **Voxel Studio API** — 3D 侧 AI（模型/动画/Runtime）

## 运行方式

```bash
npm install
npm run dev -- --host    # 开发模式
npm run build            # 生产构建（输出多入口：/ + /chii-island/ + /ghost-home/）
```

开发服务器启动后：
- **Chii Island（奇异岛）**：`http://111.230.91.60:5173/src/demos/chii-island/`
- **Ghost Home（鬼屋）**：`http://localhost:5173/src/demos/ghost-home/index.html`
